# 管理端安全能力需求评审与开发清单

更新时间：2026-10-24

## 评审结论

### 价格规则：保留规划入口，本阶段不新建重复规则引擎

当前后台的模型定价已经支持原价、折扣、现价、计价单位与不可覆盖的历史版本，能够满足官网模型广场的公开价格运营。此时再增加一套“价格规则”接口，会与模型价格版本形成两个事实来源。

进入独立价格规则开发前，需要先完成：

1. 工作区、套餐或合同价的覆盖优先级。
2. 生效时间、失效时间、发布审核和冲突检测。
3. 已完成的请求价格快照与余额账本继续补充退款/冲正、预算和支付闭环。

因此侧边栏继续显示“规划中”，当前真实配置入口仍为“大模型配置 → 配置价格”。

### 路由策略：保留规划入口，本阶段不重复建设

当前请求链路已经使用两层真实配置：

- 普通用户在控制台配置工作区路由规则，支持优先级、最低成本、最低延迟、主模型、备用模型和流量比例。
- 平台管理员配置供应商渠道与模型部署，支持渠道健康、部署优先级、权重和启停。

单独增加平台“路由策略”CRUD 会重复以上能力。后续入口应定位为平台默认策略、跨供应商成本护栏和灰度发布策略，并复用同一个路由执行内核。

### 审计日志：当前产品需要，已完成第一阶段

已增加 `audit_logs` 追加式表和 `GET /api/admin/audit-logs`。所有通过身份与角色校验、进入 `/api/admin/*` 处理器的 POST、PUT、PATCH、DELETE 成功或失败操作都会写入操作者、动作、资源、结果、IP、User-Agent、请求 ID 和时间。401/403 等鉴权拒绝事件将在认证安全事件阶段单独接入。审计记录不保存密码、API Key、供应商密钥或请求正文，且没有修改、删除接口。

当前写入是管理请求完成后的独立追加操作。写入当前采用请求后追加，审计失败会记录服务端错误但不改写已经完成的业务结果。数据库层禁止审计记录 UPDATE、DELETE 和 TRUNCATE。进入严格合规阶段前，应升级为事务 Outbox 或数据库审计流，并增加对象存储归档、保留期、导出签名和防篡改校验。

### 登录会话：当前产品需要，已完成第一阶段

已增加：

- `GET /api/admin/sessions`：按用户姓名、邮箱、IP 和 active/revoked/expired 状态查询全平台会话。
- `DELETE /api/admin/sessions/:id`：管理员即时撤销其他登录会话。

管理端页面展示用户、设备、IP、最近活动、到期时间和状态。当前管理员会话必须通过正常退出结束，避免在管理页面误撤销自己正在操作的会话。

## 后端后续接口优先级

1. **P0 账本与计费闭环**：请求价格快照、余额账本、原子扣费、退款/冲正、预算拒绝。
2. **P0 工作区邀请与所有权转移**：第一阶段已完成；继续邮件投递、成员分页和转移二次认证。
3. **P1 工作区资源审计**：成员、邀请、API Key、路由和 IP 策略已接入请求后追加；预算领域事件与事务 Outbox 待开发。
4. **P1 媒体任务基础设施**：图片/视频任务、对象存储、签名 URL、回调、幂等、取消与结果过期；音频任务已完成第一条真实异步闭环。
5. **P1 可观测性**：OpenTelemetry、Prometheus、队列积压、供应商配额、成本和告警。
6. **P1 平台运营**：用户停用原因、批量操作、模型发布审核和能力参数配置。
7. **P2 项目级隔离**：Project CRUD，以及 Project 范围的密钥、路由、日志和用量。
