# Nexus AI Router 开发清单

更新日期：2026-10-22

本文把《架构审计与演进方案》拆成可交付、可验收的开发项。状态分为：`已完成`、`进行中`、`待开发`、`受阻`。

## 已完成迭代：Stage A 多租户基础

| 状态 | 开发项 | 验收标准 |
| --- | --- | --- |
| 已完成 | 建立 Workspace、WorkspaceMember、Project 数据模型 | 每个用户至少有一个默认工作区、Owner 成员关系和默认项目 |
| 已完成 | 增加租户迁移与历史数据回填 | 既有模型、路由、密钥、日志、用量均获得非空 `workspace_id`，迁移可在现有数据库成功执行 |
| 已完成 | 建立统一 WorkspaceContextGuard | 登录用户可通过 `x-workspace-id` 选择有权限的工作区；未传时使用最早加入的有效工作区 |
| 已完成 | 模型配置按工作区隔离 | 列表、创建、修改、删除均以 `workspace_id` 为数据边界 |
| 已完成 | 路由规则按工作区隔离 | 规则名称唯一性和主备模型校验均限制在当前工作区 |
| 已完成 | API 密钥按工作区隔离 | 一个工作区最多 20 个有效密钥，创建者继续保留在 `user_id` 中用于审计 |
| 已完成 | 用量和请求日志按工作区读取 | Dashboard 与请求检索不再直接以用户 ID 作为租户 ID |
| 已完成 | 工作区查询 API | `GET /api/workspaces` 返回当前用户可访问的工作区及角色 |
| 已完成 | 新账户自动初始化工作区 | 注册、OAuth 首次登录、管理员创建用户以及历史账户登录都会幂等补齐默认工作区 |
| 已完成 | 迁移与接口烟测 | 迁移成功；默认工作区、模型、密钥、Dashboard 返回 200；伪造工作区 ID 返回 403 |
| 待开发 | 控制台工作区选择器 | 前端展示真实工作区名称，切换后统一给请求附加 `x-workspace-id` |
| 待开发 | 工作区角色权限矩阵 | Owner/Admin/Developer/Billing/Viewer 对模型、路由、密钥、账单分别授权 |
| 待开发 | 项目级资源隔离 | API 密钥、路由、日志和用量可进一步绑定 `project_id` |
| 待开发 | 用户与默认工作区原子创建 | 将用户、工作区、成员和项目初始化合并到同一个数据库事务 |

## 本次变更的兼容约定

- Web 端尚未发送 `x-workspace-id` 时，API 自动使用当前用户最早加入的有效工作区，现有页面无需同步发布即可继续运行。
- 原有 `user_id` 暂时保留为创建者或操作者字段，读取和唯一约束已经改用 `workspace_id`。完成审计字段重命名后再进入收缩迁移。
- 平台管理员角色与工作区角色保持分离。平台管理员管理平台目录和用户，工作区角色只管理租户资源。
