# Nexus 用户身份与管理后台设计

## 目标

把原来的演示登录跳转升级为可用的身份入口，并提供独立的平台级用户管理后台。工作区控制台继续承载模型、路由、密钥和用量；`/admin` 负责账户生命周期、角色和登录访问，避免把平台管理能力混入业务控制台。

## 信息架构

1. `/login`：邮箱密码登录、保持登录、错误提示和角色分流。
2. `/console`：管理员、运营和只读用户的工作区操作界面。
3. `/admin`：仅管理员可访问，当前版本落地用户目录；角色策略、审计日志和会话管理保留清晰入口，便于后续扩展。

后台的首屏顺序为：用户总览指标 → 搜索与筛选 → 用户目录 → 新建或编辑弹层。管理员可以按姓名/邮箱、角色和状态检索用户，并修改姓名、邮箱、密码、角色和状态。

## 角色与状态

| 角色 | 说明 |
| --- | --- |
| `admin` | 平台管理员，可访问 `/admin` 并管理所有用户 |
| `manager` | 运营人员，可访问工作区控制台 |
| `viewer` | 只读访问，预留给审阅和支持场景 |

| 状态 | 登录行为 |
| --- | --- |
| `active` | 可以登录并刷新会话 |
| `invited` | 尚未激活，不能登录 |
| `suspended` | 已停用，不能登录或刷新会话 |

系统不直接删除用户，使用停用保留历史关系和后续审计空间。管理员不能停用自己的当前账户。

## 会话安全

- 密码使用带随机盐的 `scrypt` 哈希存储。
- 登录签发 15 分钟访问令牌，前端仅保存在内存中。
- 刷新令牌使用 48 字节随机值，数据库只保存加盐关联后的 SHA-256 摘要。
- 刷新令牌通过 `HttpOnly`、`SameSite=Lax` Cookie 传递，每次刷新都会轮换并撤销旧会话。
- 管理接口同时经过 JWT 守卫与管理员角色守卫。
- 日志层已脱敏 `Authorization` 和 `Cookie` 请求头。

## API

- `POST /api/auth/login`
- `POST /api/auth/refresh`
- `POST /api/auth/logout`
- `GET /api/auth/me`
- `GET /api/admin/users`
- `GET /api/admin/users/summary`
- `GET /api/admin/users/:id`
- `POST /api/admin/users`
- `PATCH /api/admin/users/:id`

## 后续阶段

下一阶段可在现有入口上增加邮箱邀请与密码重置、登录限流和失败锁定、管理员操作审计、会话设备列表与远程下线、工作区级权限矩阵。当前数据模型和导航已经为这些能力保留独立边界。
