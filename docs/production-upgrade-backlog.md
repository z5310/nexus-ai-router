# 生产化改造清单

更新：2026-10-23。基于源码静态检查与专项集成验证；未执行负载测试、线上渗透测试或依赖漏洞审计。本清单补充既有 architecture-evolution-plan 与 development-checklist，实施状态以表格标记为准。

## 框架判断

实施状态与后续交付顺序统一参见 [开发清单](development-checklist.md)。下列表格保留生产化验收目标，包含部分已完成的任务，不代表全部尚未实施。

保留 Turbo + Vue 双前端 + NestJS/Fastify + PostgreSQL 的模块化单体。现阶段优先完成真实业务闭环和可靠性，无需先拆微服务或更换前端框架。BullMQ 已配置，但配置存在不代表消费者、失败队列和任务恢复已完成。

## 本轮已修改

- GitHub OAuth 邮箱仅从 verified 邮箱列表选择，优先主邮箱，避免直接信任公开 profile.email。
- OAuth 外部 HTTP 请求增加 15 秒超时，限制网络等待。
- 本地 Compose 的 PostgreSQL、Redis、MinIO 端口仅绑定回环地址。跨主机开发须另配受控网络。
- 根 AGENTS.md 记录后续开发技能选择与本清单入口。
- 模型、路由、API 密钥、用量、在线调用、成员、设置和 IP 策略已统一接入工作区权限深模块；五种角色的允许与拒绝由真实 PostgreSQL 集成测试覆盖。
- Access Token 在每次受保护请求中校验有效会话、账户状态和最新平台角色；会话撤销、密码重置、账户停用与角色调整无需等待 JWT 自然过期。
- API Key 创建与成员移除/降权共享工作区事务锁并重查成员权限；降为 Billing/Viewer 或移除成员会在同一事务撤销密钥，密钥鉴权再次校验创建者当前成员资格。真实 PostgreSQL 竞态测试通过。
- Fastify 默认不信任转发头，只有显式配置的可信代理 CIDR 可以参与客户端 IP 解析；API Key IP 策略使用统一解析结果。
- Redis Lua 脚本提供多实例共享的全局、登录及模型 RPM 限流；推理并发使用带续租和过期恢复的工作区租约。超限返回 429 与 `Retry-After`，Redis 故障返回 503。
- 请求体默认限制为 1 MiB，readiness 同时检查 PostgreSQL 与 Redis。可信代理、双实例共享限额、并发拒绝/恢复和流式释放已有专项测试。

已安装依赖，类型检查、lint 和全仓构建通过。10 个 PostgreSQL 迁移执行成功，会话事务轮换与重放撤销的真实数据库集成测试通过，覆盖并发、绝对过期、祖先重放、设备隔离、过期与未知令牌。API 健康、数据库就绪、模型列表和文档入口 HTTP 检查均返回 200。MinIO 拉取仍受镜像仓库拒绝影响，尚未运行。

前端已加入共享刷新协调：单页面合并请求、Web Locks 串行同源标签页刷新、15 秒请求超时及失败时清理访问令牌。两项逻辑测试通过；不同源（含不同端口）不共享锁，不支持 Web Locks 的环境仅有单页面协调，浏览器端到端验证待完成。

## P2：按使用证据推进

- 模型对比和推荐：按任务、预算、延迟筛选，公开评分来源和更新时间。
- 成本治理：按项目/密钥预算、异常消耗提醒、每日费用报表。

- 企业能力：SSO、细粒度项目权限、数据保留策略；有客户需求后实施。
- 扩展 Embedding/Image/Audio 前明确计量单位、异步任务状态和取消语义。

## 推荐交付顺序

1. 安全与测试基线：会话竞争、权限矩阵和限流已完成；继续处理生产种子约束、安全响应头及统一超时。
2. 可重复发布：CI、镜像、迁移作业、备份恢复、监控。
3. 商业闭环：预算账本、对账、实际路由、供应商凭证数据面接入。
4. 客户闭环：首调用引导、真实账单和成员设置，再做推荐与增长。

每批以表中验收条件结束；先确定目标客户、付费方式（充值/后付费/BYOK）、初期并发目标、部署地区与数据保留要求，再细化计费和容量设计。
