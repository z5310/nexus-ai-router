## 本轮已修改

- GitHub OAuth 邮箱仅从 verified 邮箱列表选择，优先主邮箱，避免直接信任公开 profile.email。
- OAuth 外部 HTTP 请求增加 15 秒超时，限制网络等待。
- 本地 Compose 的 PostgreSQL、Redis、MinIO 端口仅绑定回环地址。跨主机开发须另配受控网络。
- 根 AGENTS.md 记录后续开发技能选择与本清单入口。
- 模型、路由、API 密钥、用量、在线调用、成员、设置和 IP 策略已统一接入工作区权限深模块；五种角色的允许与拒绝由真实 PostgreSQL 集成测试覆盖。
- Access Token 在每次受保护请求中校验有效会话、账户状态和最新平台角色；会话撤销、密码重置、账户停用与角色调整无需等待 JWT 自然过期。
- API Key 创建与成员移除/降权共享工作区事务锁并重查成员权限；降为 Billing/Viewer 或移除成员会在同一事务撤销密钥，密钥鉴权再次校验创建者当前成员资格。真实 PostgreSQL 竞态测试通过。
- Fastify 默认不信任转发头，只有显式配置的可信代理 CIDR 可以参与客户端 IP 解析；API Key IP 策略使用统一解析结果。
- Redis Lua 脚本提供多实例共享的全局、登录及模型 RPM 限流；推理并发使用带续租和过期恢复的工作区租约。超限返回 429 与 `Retry-After`，Redis 故障返回 503。
- 请求体默认限制为 1 MiB，readiness 同时检查 PostgreSQL 与 Redis。可信代理、双实例共享限额、并发拒绝/恢复和流式释放已有专项测试。
- 工作区邀请已实现一次性哈希令牌、七天有效期、邮箱绑定、重发/撤销/过期/重放拒绝；Owner 转移使用事务和唯一索引保证唯一所有者，变更写入追加式审计。邮件投递、分页和转移二次认证待开发。
- OpenAI 兼容供应商数据面已按模型部署直接读取渠道、校验运行环境和精确域名白名单，并在出站前按需解密绑定凭证；Admin 可执行无消耗连接检查和真实 JSON/SSE/取消验收。DeepSeek 官方接口与隔离工作区首次调用已通过；原生 Anthropic/Google、异常场景、周期探测和生产 KMS 待完成。

## 2026-10-27 可观测性与有界 readiness（已验收）

新增 Prometheus 抓取端点，覆盖 HTTP 请求量/延迟、推理成功失败/总延迟/首 Token、供应商尝试与延迟、PostgreSQL/Redis readiness、音频队列积压、供应商渠道持久健康状态和采集器状态。指标标签不包含工作区、用户、请求 ID、渠道 ID、密钥或提示词；HTTP 使用路由模板控制基数。所有 HTTP 响应返回应用生成的 `x-request-id`。

Readiness 的 PostgreSQL 和 Redis 检查并行执行且分别受 2 秒默认超时约束；队列和渠道抓取分别受 1 秒默认超时约束。新增 API 错误率、依赖失败、首 Token P95、供应商失败率、队列积压及采集失败规则。单元测试验证超时边界和指标标签，真实 PostgreSQL/Redis/BullMQ HTTP 集成测试验证 `/api/health`、`/api/ready`、`/metrics` 和请求关联头。详细运行方式见 [可观测性与告警基线](observability-operations.md)。OpenTelemetry trace、周期供应商主动探测和 Alertmanager 生产路由仍待开发。

## 2026-10-27 持久化计量 Outbox（已验收）

推理请求日志、供应商尝试链和版本化计量事件现在于同一 PostgreSQL 事务提交。BullMQ 只承担低延迟唤醒；API 启动及周期扫描会从数据库补投待处理事件，因此 Redis 短时故障不会丢失计量事实。消费者在单个事务中锁定事件、更新 `usage_buckets` 并标记完成，多实例竞争、重复投递和确认丢失均不会重复聚合。

新增指数退避、最大尝试次数、死信状态、平台管理员查询与重放接口，以及待处理/死信指标和告警。迁移 `1760000026000-MeteringOutbox` 已执行，重复迁移无待执行项。真实 PostgreSQL/Redis 集成测试覆盖投递故障恢复、并发消费、重复消费、无效载荷进入死信、修复重放和管理接口权限/参数边界；受影响的价格快照、请求尝试、路由、Chat 计费、推理并发与可观测性回归通过。运维步骤见 [持久化计量 Outbox 运维说明](metering-outbox-operations.md)。
