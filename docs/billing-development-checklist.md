# 计费账本开发清单

更新：2026-10-26。

## 第一阶段已验收：独立账本模块

- 新增 `billing_accounts`、`billing_reservations`、`billing_ledger`，迁移 `1760000019000-BillingLedger` 已执行。
- 内部 `BillingService` 提供入账、预占、结算与释放。金额以 CNY 字符串传入，数据库以整数微元保存，最大六位小数，不进行隐式舍入或换汇。
- 每次操作在事务中锁定工作区账户，余额、冻结额度、预占状态和流水同时提交。余额与冻结额度不能为负。
- 入账按工作区及业务标识幂等；预占按工作区及请求标识幂等。同标识改变金额返回 409。结算与释放只能从 held 进入一个终态，重复相同操作不会重复扣费或返还。
- 实际金额超过预占时，仅允许使用该工作区剩余可用额度；不足返回 402，原预占保持 held，等待对账处置，不占用其他请求冻结的额度。
- 流水禁止 UPDATE、DELETE、TRUNCATE；修正应追加补偿流水。数据库特权维护和灾备操作不属于普通应用接口。
- `GET /api/billing/balance` 返回 CNY 可用/冻结金额；`GET /api/billing/ledger` 返回倒序游标分页，每页最多 50 条。沿用 `usage:read` 权限和服务器工作区上下文。未建立账户返回真实零余额及空流水。
- 入账只开放内部模块接口，没有公开赠送、充值、扣费或支付回调入口，不接受前端自行声明已付款。

## 已通过验证

- `npm run test:billing -w @gateway/api`：金额精度、真实 PostgreSQL 多连接竞争、幂等、结算/释放竞态、超额结算、跨工作区读取隔离、游标分页、流水汇总对账及不可修改约束。
- Nest/Fastify HTTP 测试：匿名 401、当前工作区 200、跨工作区 403、非法游标 400，公开入账入口不存在。测试用户及工作区会清理；并发账本测试在隔离 schema 中执行并清理。

## 第二阶段已验收：Chat 受控计费接线

- 新增迁移 `1760000020000-ChatBilling`，持久化父请求 ID、尝试标识、价格快照、发送阶段、实际用量、待结算金额与待对账原因。每次上游尝试使用独立预占，故障转移不覆盖上一次的资金记录。
- 仅 `BILLING_PREPAID_WORKSPACE_IDS` 显式列出的工作区启用；默认空，不修改既有账户的费用策略。2026-10-26 本地 DeepSeek 验收工作区已显式启用，其他工作区仍保持关闭。
- 启用后按 UTF-8 字节数与消息开销估算输入，按调用的 `max_tokens` 预占输出；未传时使用并向上游发送 2048 上限。估算不是模型 tokenizer 保证，超额结算只能使用当前可用余额，不能动用其他请求预占。
- 余额不足在上游发送前返回 402；同一次尝试不可重复发往上游。非流式 `/v1/chat/completions` 已支持公开 `Idempotency-Key`，相同工作区、键和载荷复用首次结果；流式请求幂等仍待开发。
- JSON 完整用量、完整 SSE 加用量才自动结算。适配器不再把 JSON 缺失用量补成零，SSE 缺少 `[DONE]` 会作为中断处理。
- 只有适配器明确保证未发送请求时自动释放，例如网关未配置、发出前已取消。一般超时、连接错误、途中取消或缺失用量都保留冻结额度并进入 `review`，不推断为免费。
- 确认的结算/释放结果先持久化，再更新余额；进程内每 30 秒扫描最多 50 项已知结果，支持多实例幂等恢复。结算余额不足保留已知金额，补足额度后可继续结算。请求日志写入与账本仍是独立事务，账本证据不依赖请求日志成功写入。
- 超过 15 分钟的 `prepared` 记录可安全释放；`dispatched` 记录只转待人工对账，不自动释放。长时间仍运行的请求也可能保留为待对账，需要后续供应商回查完善。
- `GET /api/billing/status` 返回当前工作区是否启用 Chat 计费；`GET /api/billing/pending` 返回该工作区最多 50 条未结预占，不返回提示词或供应商密钥。沿用 `usage:read` 和工作区隔离。
- `/v1/chat/completions` 响应增加 `x-request-id`，用于关联请求日志、尝试链与预占父请求。

验证：`test:chat-billing` 覆盖默认关闭、JSON/SSE 结算、调用前 402、重复尝试、确定未发送释放、未知用量保留、故障转移、取消、持久结果恢复、超额金额不足和补足后恢复。`test:provider-usage` 使用本地模拟网关验证用量缺失和 SSE 截断；HTTP 验证状态/待对账隔离及启用后 Playground 的 402。既有账本、路由、并发和价格快照测试通过。2026-10-26 DeepSeek 官方接口真实商业计费验收通过：平台管理员经审计接口授予 `¥1.000000` 测试额度；调用使用 36 个输入 Token、23 个输出 Token，先预占 `¥0.015318`，按价格版本 `84440b1b-dbb4-4a0d-a0c9-95046d641cf1` 实结 `¥0.000230` 并释放 `¥0.015088` 差额；最终可用余额 `¥0.999770`、冻结余额 `¥0.000000`，请求日志、预占和账本金额一致。该额度是验收测试额度，不代表支付到账。

## 第三阶段已验收：账户界面、额度授予与人工对账

- Console `/console/billing` 显示真实六位小数余额、冻结额度、Chat 计费状态、未结预占及游标流水。调用类流水展示实际计费模型、公开模型 ID、输入/输出 Token、当次单价和父请求 ID，并可带请求 ID 跳转调用日志；新调用把模型名称、公开 ID 和供应商随价格固化，历史旧快照通过模型 ID 兼容展示。查询 key 带工作区 ID，支持加载、错误重试及空态；账户和未结预占每 30 秒刷新，流水支持手动刷新和加载更多，不以零余额掩盖请求失败。关闭自动计费时仍显示已有额度和流水。
- Admin `/admin/billing` 支持工作区搜索分页、账户与预占读取、流水翻页、财务审计、额度授予及人工处置。仅平台 admin 可访问；普通账户访问后台返回 403。
- 授予额度要求原因、核实依据及 UUID 操作编号；只向有效工作区授予，不代表支付到账，也不改变自动计费启用配置。
- 仅 `held + review` 的 Chat 预占允许人工处置，处理中或待自动结算的记录不能强制覆盖。人工结算由核实后的输入/输出 Token 和已有价格快照计算，释放则记录确认无费用的依据。提交前提供只读金额预览，事务内再次检查状态和额度。
- 管理操作锁定工作区账户并重查操作者的有效 admin 身份；余额、预占、流水和审计同一事务提交。重复同操作编号、同内容与同操作者返回首次回执，改变内容返回 409。不同操作编号竞争处置同一预占仅一次成功。
- 新增迁移 `1760000021000-BillingAdminAudit`；审计保存操作者身份快照、原因、核实依据、业务标识和前后状态，禁止修改、删除及清空；存在记录时拒绝该迁移回滚。
- 财务表单使用原生 modal dialog、两步确认、提交禁用、Escape 关闭及焦点恢复。提交前保留按管理员/工作区隔离的 sessionStorage 操作编号与内容；结果未知时可按原内容重试，避免刷新后直接生成新操作。浏览器确认页面已检查，网络异常后的恢复交互未做完整浏览器故障注入。
- 金额核心计算改用 BigInt 微元，Chat 自动结算与人工结算均不经 Number 金额往返。新增大金额精度用例。

新增接口：

- `GET /api/admin/billing/workspaces`：工作区查找，每页 20 项。
- `GET /api/admin/billing/:workspaceId`：账户、未结预占、首屏流水与最近 50 条审计。
- `GET /api/admin/billing/:workspaceId/ledger`：游标流水。
- `POST /api/admin/billing/:workspaceId/grants`：额度授予。
- `POST /api/admin/billing/:workspaceId/reservations/:reference/preview`：只读处置预览。
- `POST /api/admin/billing/:workspaceId/reservations/:reference/resolve`：人工结算或释放。

验证：`test:admin-billing` 覆盖实际数据库并发授予、重复回执、内容冲突、越权、审计失败全事务回滚、快照定价、仅 review 可处理、结算/释放竞态、额度不足保留和审计不可变。账本集成测试覆盖调用流水的模型身份、用量、价格快照和父请求关联；价格快照测试覆盖模型名称、公开 ID 与供应商固化。HTTP 覆盖普通用户 403、管理员读取、非法路径和参数拒绝。既有计费、Chat 恢复和价格测试通过。浏览器验证桌面及 390px 无横向溢出，DeepSeek 历史流水可显示实际模型并跳转筛选对应调用；2026-10-26 已通过正式管理接口向 DeepSeek 验收工作区授予 `¥1.000000` 测试额度，操作编号、原因、依据、变更前余额和结果均已写入不可变财务审计。
