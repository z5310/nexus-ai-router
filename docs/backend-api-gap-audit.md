# 后端接口完成度与缺口清单

更新日期：2026-10-24

本文以当前 `apps/api` 的 Controller、Service、数据库实体、迁移和集成测试为准，区分“接口存在”和“业务闭环已完成”。状态含义：

- `已完成`：已有接口、持久化、权限边界，并有对应验证。
- `部分完成`：已有数据结构或 CRUD，但尚未进入真实运行链路。
- `未开发`：当前没有可用后端接口或核心领域实现。
- `暂缓`：实现需要先明确安全边界或外部系统。

## 当前结论

后端已经具备账号、会话、工作区隔离、成员管理、工作区模型配置、API Key、公共模型目录、排行榜、Chat JSON/SSE、基础日志与用量聚合。路由规则现已进入真实推理链路，支持稳定流量分桶、策略排序、主备故障转移和上游尝试明细。当前离“可商业运行的多模型路由平台”仍有以下核心缺口：

1. **可信数据面已完成 OpenAI 兼容第一阶段。** Channel/Deployment、部署级目标选择、并发、健康状态和连续失败熔断已进入推理链；配置部署时会按渠道在白名单目标调用前解密对应凭证，未配置部署时继续兼容 `PROVIDER_GATEWAY_URL`。DeepSeek 低额度商业 Key 已通过真实验收；原生 Anthropic/Google、周期主动探测与严格半开仍待完成。
2. **账本及 Chat 受控接线已完成，商业运营闭环仍待完善。** 已有余额、预占/结算/释放、不可变流水和已知结果恢复；默认不启用自动扣费。财务授予/人工对账审计及账单前端已完成第一阶段，DeepSeek 真实商业计费验收已通过；预算、支付、退款/冲正与供应商用量回查待开发。
3. **媒体和异步任务只完成 Audio 第一阶段。** Audio 已有登录态创建、查询、排队取消、持久任务和 Worker；Image、Video、Embedding 仍只有模型目录。Audio 也仍缺账本、对象存储、幂等、DLQ 和真实供应商验收。

## 2026-10-23 路由执行阶段交付

- `RoutingExecutorService` 根据请求模型类型查找启用规则，并用 `requestId + ruleId` 进行可复现的流量分桶。
- `priority` 保持主备顺序；`lowest_cost` 和 `lowest_latency` 会在同类型、仍可用的主备候选中排序。
- 非流式调用在上游失败时依次尝试候选；流式调用只允许在响应建立前切换，已经开始输出后不透明重试。
- `request_logs` 记录请求模型、实际模型、命中规则、尝试次数、首 Token 延迟和错误码。
- `inference_attempts` 按顺序记录每次目标模型、供应商、状态、耗时和脱敏错误。
- `GET /api/dashboard/requests/:requestId` 返回完整尝试链，并继续受工作区 `usage:read` 权限隔离。

## 2026-10-23 渠道与部署阶段交付

- `provider_channels` 将供应商、环境、加密凭证、区域、超时、最大并发和健康状态建模为独立配置。
- `model_deployments` 将平台模型映射到渠道与上游模型 ID；同健康度、同优先级部署按 `requestId` 做稳定权重选择。
- 推理执行在模型 fallback 内继续执行渠道 fallback，非流式和 SSE 建连前失败均可换下一个部署。
- 工作区并发之外新增渠道级 Redis 租约；部署超时覆盖全局默认超时。
- 渠道失败计数使用数据库原子更新；连续三次失败进入 `unhealthy` 和 60 秒冷却，成功清零恢复。
- `inference_attempts` 保存渠道和部署 UUID，删除运行配置不会抹掉历史调用标识。
- Admin `/admin/channels` 使用真实接口维护渠道与部署，新增页面样式使用 UnoCSS。
