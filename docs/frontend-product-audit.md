# Web、控制台与管理后台产品审计

更新日期：2026-10-27

## 审计范围与结论

本次以正在运行的公开模型广场、普通用户控制台和平台管理后台为视觉依据，并逐项对照 Vue 路由、页面 API 封装、NestJS Controller 以及共享 contracts。重点检查模型发现、工作区开通、密钥创建、首次调用、调用记录和平台运营这条核心链路。

三个前端已经形成一致的黑绿视觉语言，登录边界也正确分开：普通用户进入 Console，平台角色为 `admin` 的内部人员才能进入独立的 Admin 应用。当前主要风险不在视觉框架，而在数据可信度、操作闭环和前端工程边界。

核心闭环已从“能配置模型”推进到真实 DeepSeek 调用：渠道绑定加密凭证可在白名单目标完成模型发现、JSON、SSE、取消传播和用量验收。Console 已新增首次调用向导，可按真实状态启用模型、创建一次性展示的 API Key、复制 curl、发送首请求并跳转日志；请求详情、真实账本、工作区切换和管理端主要运营页面也已陆续接入。

## 必须优先修正的问题

### P0：数据可信和首次调用闭环

1. **认证后的控制台禁止演示数据回退。** Dashboard 和日志接口失败时只显示错误、重试和故障编号；无数据时显示真实空态。公开营销页面可以保留演示内容，但必须明显标注来源和更新时间。
2. **账单页已接真实账本。** 展示余额、冻结、周期消费、模型趋势/排行及逐笔流水；自动扣费状态与支付到账明确区分，禁止用固定金额或演示交易回退。
3. **增加工作区开通向导。** 固定四步：启用一个模型、创建 API Key、复制可运行 SDK 示例、观察首个成功请求。每一步从真实资源状态计算完成度。
4. **打通工作区切换。** `GET /api/workspaces` 已存在；选择后统一写入 `x-workspace-id`，所有 Vue Query key 带工作区 ID，切换时取消旧请求并清理旧缓存。
5. **补充真实请求详情。** 日志列表进入详情抽屉，展示 request ID、目标模型、最终供应商、尝试链、状态码、token、费用、首 Token/总耗时和错误摘要；提示词默认不展示全文。
6. **路由规则已进入真实执行链路。** 前端下一步应展示运行状态、命中量、实际模型和故障转移统计，并从请求详情接口读取尝试链。

### P0：平台运营闭环

1. **用户管理接出现有接口。** 增加用户详情抽屉、创建用户、修改平台角色/状态、重置密码和强制撤销会话；所有破坏性操作二次确认并显示影响范围。
2. **供应商渠道页面已完成第一阶段。** 已支持凭证创建/启停/删除，并显示尾号、环境、区域、超时、并发、健康/熔断、模型部署和上下游模型映射；下一步补凭证轮换、受控主动探测和审计。真实密钥出站仍需另行授权。
3. **价格版本第一阶段已完成。** Admin 可配置输入/输出原价、折扣和计价单位，成交价由后端计算并产生历史版本。下一步增加模型基本资料、类型、能力、上下文、评分来源、排序、媒体参数和预约生效。
4. **为即时开关增加可恢复反馈。** 上下线、精选和生命周期修改显示保存中、成功/失败 Toast；上线/停用需确认并说明会影响模型广场、工作区和 API。
5. **平台角色重新命名。** `admin/manager/viewer` 在 Admin 中分别显示为“平台管理员/平台运营/平台观察员”；工作区的 Owner/Admin/Developer/Billing/Viewer 只出现在 Console。

## 前端工程调整

1. **拆分页面模块。** `apps/admin/src/pages/dashboard/index.vue` 应拆成 `overview`、`models`、`users`、`providers` 页面目录；Console 的 `section.vue` 同样拆成每个路由独立页面及本页 `cmp/api`。这能让权限、请求状态和测试边界与业务页面一致。
2. **共享 HTTP 深模块。** Web 与 Admin 的 Axios、Token 刷新、错误映射目前几乎完全重复；下沉到独立 `packages/http-client`，由两个应用注入 base URL、令牌存储和未授权跳转策略。
3. **统一业务组件与 UnoCSS 边界。** Console/Admin 已接入 Ant Design Vue 4 和共享 Nexus 主题，UnoCSS 负责布局与页面组合。登录和 Console 高频配置表单已完成首批迁移；Admin 运营表单、数据表和分页继续按页面迁移，旧样式随迁移删除，避免再次形成全局 CSS 单体。详见 [组件体系说明](frontend-component-system.md)。
4. **继续细化路由拆包。** Web 与 Admin 顶层路由已改为动态 import，官网、认证、Console、Docs 和 Admin 页面形成独立 chunk；下一步把体积较大的 Console `section.vue` 与 Admin Dashboard 继续拆成每个业务模块的独立路由组件，并建立性能预算。
5. **查询缓存必须包含租户。** `['dashboard-overview']`、`['console-models']` 等 key 需要加入 workspace ID；分页、搜索和过滤参数也进入 key，避免切换后串数据。
6. **建立权限感知组件。** 根据服务端返回的工作区角色控制创建、编辑、删除按钮；后端继续作为最终授权边界。禁止只靠点击后返回 403 来表达权限。
7. **统一真实状态组件。** 共享 Loading、Empty、Error、PermissionDenied、Unavailable 和 Retry，禁止在认证产品页面用 fallback 数据掩盖错误。

## 视觉与可访问性调整

- Console 大量正文和导航只有 7–10px，桌面和移动端都偏小；正文建议不低于 13–14px，辅助文字不低于 12px。
- 多个图标按钮只有 28–30px，移动端触控目标建议达到 44×44px。
- Console 的 680/760px 宽表格在窄屏只显示前几列；模型、密钥、日志改为移动端卡片或提供明确横向滚动、冻结首列和操作列。
- Admin 的精选开关和状态开关缺少可访问名称及 `aria-pressed`；分页按钮也需要明确标签。
- Console 弹窗已有 `role=dialog` 和 Escape 关闭，但缺少打开后的初始焦点、焦点圈定和关闭后的焦点恢复。
- User Menu 的 `aria-expanded`、菜单角色和退出入口实现较完整，可以作为其他弹层交互的基准。
